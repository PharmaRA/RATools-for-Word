# 用户手册与文档站实施记录

分支：`docs/user-manual`。目标：按实际功能区、宏注册表及窗体行为编写中文手册，覆盖每个用户入口，并将 README 调整为下载与入门入口。

## 实施顺序

1. 核对功能区 XML、17 项有效注册宏及直接依赖，整理处理范围、步骤、输出、保存方式和限制。
2. 在 `docs/manual/` 编写安装、功能、场景、排错及扩展指南；逐项覆盖简单按钮，复杂宏独立成页。
3. 使用 MkDocs Material 生成静态站点，提供中文搜索、导航、截图、本地预览与 GitHub Pages 工作流。开发维护文档继续从 `docs/README.md` 进入。
4. 精简根 README，保留定位、兼容性边界、下载、最短入门步骤及完整手册入口。
5. 校验实际入口覆盖、Markdown 链接、站点严格构建、浏览器导航与中文搜索，并执行只读子代理审阅。

## 交付边界

- 本次仅修改文档及文档站基础设施，不修改 VBA、模板或发布包。
- 说明以当前分支源码为准；安装截图来自仓库既有资料，标明旧版界面可能存在差异。
- 不把已有源码行为推断为所有 Office 版本均通过测试。
- 工作流就绪不等于网站已上线；远程发布需要仓库启用 Pages，并实际执行发布工作流。
- 已将原 README、docs 入口及 .gitignore 备份至 `backups/docs-user-manual-20261110/`。

## 验收

- 每个有效 Ribbon 动作、Word 原生入口和宏注册项都映射到具体手册章节；注释掉的入口不计入。
- 所有功能都有可操作说明；批量功能明确是否递归、原文件是否保存、结果在哪里以及失败时如何处理。
- 手册在 GitHub Markdown 和生成的网站均可阅读；站内链接和图片无失效。
- 本地严格构建、浏览器导航和中文检索有实际验证结果；审阅发现修正后再交付。

### 已处理的验证与审阅发现

- 初次 `--dirty --strict` 构建被 MkDocs 自带的 dirty 警告中止。改为新目录专用构建入口，拒绝已有路径，不清空旧产物，随后严格构建通过。
- 补充格式修订兼容处理的主文档范围限制，避免把提示数量说成所有文字区域的统计。
- 补充清稿发生中途异常可能停止后续批次，以及已保存文件不会整体回滚的说明。
- 对 Word 原生分节入口使用与版本无关的操作描述，不声称仓库无法证明的具体菜单布局。
- 浏览器工具单独设置搜索框值后没有触发检索；补充键盘事件后，中文结果和跳转均正常，未因此修改站点代码。
- Material 的 2027-05-05 维护结束日期已经核实并记录在维护指南中。
## Starlight 视觉改造（docs/starlight-preview）

用户认为 Material 默认外观偏旧，已在独立分支改为 Astro Starlight，并保留 `docs/manual/` 作为唯一正文来源。

- 首页：重做黑金品牌视觉、任务入口卡片、首次使用路径、截图展示与完整目录。
